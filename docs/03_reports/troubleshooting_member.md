# 회원가입 검증 트러블 슈팅

## 📌 문제 발생

1. 문제 유형 (핵심 태그) 정의

- 파라미터 바인딩 오류 / 스프링 MVC Validation 예외 / 400 Bad Request
1. 어떤 기능에서 문제가 발생했는가?
    - 회원가입 폼에서 이메일 형식을 틀리게 적거나 빈칸으로 제출했을 때, 다시 가입 화면으로 돌아가서 폼 아래에 에러 메시지를 띄워주기를 기대했습니다. 하지만 폼 화면으로 돌아가는 것이 아니라, 브라우저에 400 Bad Request (잘못된 요청) 에러 페이지가 뜨는 현상이 발생했습니다.

---

## 🔍 원인 분석

- 스프링 부트(Spring MVC)에서는 폼 데이터를 @Valid로 검증할 때, 에러가 발생하면 그 에러를 담아둘 바구니 역할을 하는 BindingResult 객체가 필요합니다. 이때 BindingResult 객체는 반드시 검증할 객체 바로 뒤에 위치해야 합니다.
- 기존 코드에서는 MemberDto와 BindingResult 사이에 @RequestParam이 끼어있어서, 에러가 발생했습니다.

---

## 🛠 해결 방법

- 컨트롤러 메서드의 파라미터 순서를 변경하여, BindingResult를 @Valid가 선언된 MemberDto 객체 바로 뒤로 옮겼습니다.

---

## 🧠 배운점

- 스프링 프레임워크가 제공하는 기능을 사용하려면 개발자가 반드시 지켜야 하는 규칙이 존재한다는 것을 느꼈습니다.
- 오류가 났을 때는 내가 짠 로직만 확인하는 것이 아니라 프레임워크의 기본 동작 구조를 다시 한 번 확인해보는 시야를 가져야 한다는 것을 깨달았습니다.
