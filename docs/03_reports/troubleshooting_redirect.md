# 리다이렉트 트러블 슈팅

📌 **문제 발생**

- **문제 유형 (핵심 태그):** 경로 매핑 및 리다이렉트 오류 / 라우팅 문제
- **어떤 기능에서 문제가 발생했는가? / 문제 상황:**
    - 회원 로그인 성공 후 메인 페이지로 이동하기 위해 컨트롤러에서 `return "redirect:/index.html";`을 실행했으나, 메인 페이지로 정상적으로 넘어가지 못하고 로딩이 멈추거나 리다이렉트가 올바르게 수행되지 않는 현상 발생.

🔍 **원인 분석**

- **왜 발생했는가? / 어떤 코드/구조에서 문제가 있었는가?**
    - 타임리프(Thymeleaf) 및 스프링 MVC 환경에서 `redirect:`를 사용할 때는 파일 확장자(`html`)를 포함한 정적 파일 경로(`redirect:/index.html`)가 아니라, 스프링이 관리하는 경로 매핑 주소(`/`)를 타도록 지정해야 합니다.
    - 루트 경로(`/`)를 담당하는 컨트롤러(`@GetMapping("/")`)가 존재함에도 불구하고 파일명 직접 접근 형태의 리다이렉트를 사용하여 경로 매핑이 꼬였기 때문입니다.

🛠 **해결 방법**

- **어떻게 해결했는가?**Java
    - 로그인 성공 시 리다이렉트 반환 값을 확장자를 제외한 루트 경로(`redirect:/`)로 수정하여, 스프링의 루트 컨트롤러를 정상적으로 타도록 변경함.

    ```
    @PostMapping("/login")
    public String login(@RequestParam String email, @RequestParam String password){
        if (memberService.login(email, password) != null) {
            return "redirect:/"; // 수정 완료
        } else {
            return "member/login";
        }
    }
    ```


🧠 **배운점**

- 스프링 부트에서 페이지 이동을 처리할 때 타임리프 뷰 리졸버와 리다이렉트(`redirect:`)의 동작 방식을 정확히 이해해야 함을 깨달았습니다.
- 파일을 직접 호출하는 방식(`index.html`)보다 서버의 매핑 경로(`/`)를 통해 라우팅하는 것이 스프링 MVC의 구조상 올바른 접근이라는 점을 학습했습니다.
