# 🍳 냉부 (레시피 & 요리 꿀팁 공유 플랫폼)

> 사용자들이 자신만의 레시피와 유용한 요리 꿀팁을 공유하고, 서로 팔로우하며 소통할 수 있는 커뮤니티 웹 서비스입니다.

---

## 프로젝트 기간
- **개발 기간**: 2026.07.24 ~ 2026.08.06
- **참여 인원**: 백엔드 유동훈, 이유림, 이지원, 최원일

---

##  Tech Stack (기술 스택)
- **Backend**: Java, Spring Boot, JDBC
- **Frontend**: HTML5, CSS3, Thymeleaf, JavaScript
- **Database**: MySQL
- **Version Control**: Git, GitHub

---

## 주요 기능 (Key Features)
1. **회원 관리**
    - 회원가입, 로그인, 비밀번호 찾기, 회원정보 수정 및 회원 탈퇴
2. **레시피 게시판**
    - 레시피 등록, 수정, 삭제 및 상세 조회 (최신순/조회순 정렬)
    - 스크랩(즐겨찾기) 및 좋아요(추천) 기능
    - 댓글 작성 및 관리
3. **요리 꿀팁 게시판**
    - 나만의 꿀팁 등록, 수정, 삭제 및 상세 조회 (최신순/조회순 정렬)
4. **마이페이지 & 소셜(팔로우)**
    - 내가 쓴 글 및 스크랩한 레시피 모아보기
    - 다른 사용자의 프로필 방문 및 팔로우/언팔로우 기능
    - 팔로우한 유저들의 최신 레시피를 모아보는 '팔로우 피드' 제공
5. **오늘 뭐 먹지?**
    - 카테고리별 랜덤 레시피 추천 기능

---

## Database 구조 (ERD)
> `member`, `category`, `post`, `reply`, `good`, `follow` 테이블 구조로 설계되었습니다.

## 평가
■ 1. 주제 선정 (10점)
[강점]
(주강사) 요리 레시피 공유 커뮤니티라는 명확한 서비스 목적과 문제 해결 가치를 지닌 주제를 선정했습니다. 추천순 및 명예의전당 정렬, 밥플루언서, 팔로우, 스크랩 기능 등을 구성하여 자바 OOP, Spring MVC, Spring JDBC, MySQL RDBMS 조인, Thymeleaf SSR, 세션 기반 회원 관리 등 과정에서 배운 기술 내용들을 기능 구조에 잘 반영했습니다.
(보조강사) 프로젝트 목적에 적합한 커뮤니티성 게시판을 선정했고, 교육 과정에서 학습한 내용을 실제 기능에 적용하기에 적절한 주제입니다.

[보완사항]
(주강사) 영양성분 데이터 처리나 조건별 복합 검색 기능을 추가하여 배운 SQL 서브쿼리 및 그룹화(GROUP BY, HAVING) 활용 범위를 넓히는 방안을 추천합니다.
(보조강사) 상세 검색 등 레시피 서비스만의 기능이 추가되면 주제의 특징이 더 잘 드러날 것 같습니다.

■ 2. 계획 수립 (20점)
[강점]
(주강사) 프로젝트 초반부터 문서 정리가 체계적으로 이루어졌으며, 기획서에 회원, 레시피, 요리꿀팁, 댓글 등 도메인별 수직 슬라이스 방식으로 4명의 팀원 역할을 나눴습니다. 깃허브 프로젝트와 마일스톤 관리를 적극적으로 활용하여 세부 구현 과제와 개발 일정을 순차적으로 수립하고 안정적으로 운영했습니다.
(보조강사) 개발 시작 전 필요한 문서를 비교적 상세하게 작성했고, 기능을 기준으로 팀원별 담당 영역을 나누어 진행했습니다.

[보완사항]
(주강사) 일정 추정 시 이슈별 예상 소요 시간을 라벨링해 두면 작업 진행을 파악하기에 용이할 것입니다.
(보조강사) 예상 작업 기간이나 완료 목표일을 조금 더 구체적으로 관리했다면 일정 관리 측면에서 더 좋을 것 같습니다.

■ 3. 분석 및 정의 (20점)
[강점]
(주강사) 요구사항 명세서에 기능별 ID, 우선순위, 담당자를 명확히 분류하고 1순위 핵심 기능을 충실하게 정의했습니다.
(보조강사) 요구사항을 기능 단위로 구분하고 우선순위와 담당자를 지정하여 실제 개발 시 참고할 수 있도록 정리했고, 우선적으로 구현해야 하는 핵심 기능이 명확하게 구분되어 있어 개발 방향을 파악하기 쉬웠습니다.

[보완사항]
(주강사) 1순위 회원가입 시 예외 메시지 연동 부분과 3순위 기능(밥플루언서 랭킹 자동 반영 및 프로필 이미지 업로드 연동)의 처리 세부사항이 일부 미비하여 이를 보완하면 좋습니다.
(보조강사) 몇몇 기능은 정상적인 경우뿐만 아니라 실패하거나 예외가 발생하는 경우까지 정의하면 좋을 것 같습니다.

■ 4. 기획 및 설계 (20점)
1)FE
[강점]
(주강사) HTML5, CSS3, JavaScript 및 Thymeleaf 뷰 템플릿 구조 기반으로 TUI Editor(Toast UI Editor)를 도입하여 글 작성 폼 화면을 구현했습니다.
(보조강사) 단순 HTML 화면 구성에 그치지 않고 외부 라이브러리를 실제 기능에 적용한 것이 인상적이었습니다.

[보완사항]
(주강사) HTML 폼 요소의 기본 유효성 검증 속성(required, maxlength 등) 입력을 보완할 필요가 있습니다.
(보조강사) 검증 처리 로직이 살짝 부실한 것 같습니다.

2)BE
[강점]
(주강사) DB 설계를 중심으로 MEMBER, POST, REPLY, GOOD, CATEGORY, FOLLOW 등 6개 핵심 테이블의 정규화 및 관계 외래키 매핑을 ERD와 DDL 스크립트로 명확하게 정의했습니다.
(보조강사) 기능 구현에 필요한 외래키 관계가 비교적 명확하게 설계되어 있었습니다.

[보완사항]
(주강사) 게시글 추천순 정렬 시 데이터베이스 복합 정렬 조건 및 페이징 처리를 명확히 처리할 필요가 있습니다.
(보조강사) 여러 데이터를 기준으로 목록을 조회하는 기능은 명확한 조회 기준을 정하면 좋을 것 같습니다.

■ 5. 개발 및 테스트 (20점)
1)FE
[강점]
(주강사) Thymeleaf 공통 레이아웃 프래그먼트(th:replace) 모듈화와 th:href, th:action 등 동적 속성을 적절히 활용했으며, TUI Editor 적용 시 발생한 헤더 검색 폼과의 선택자 충돌을 명시적 선택자로 구분하여 에디터 데이터 추출을 연동했습니다.
(보조강사) 공통으로 사용되는 화면을 Thymeleaf Fragment로 분리하여 중복을 줄였으며, 화면 이동 및 폼 전송에도 Thymeleaf 문법을 적절하게 사용했습니다.

[보완사항]
(주강사) 폼 입력 전송 시 서버 응답 및 유효성 검증 안내 메시지 처리를 추가하면 좋습니다.
(보조강사) 예외 발생 시 해당 내용에 대한 요약 내용을 사용자에게 전달하면 좋을 것 같습니다.

2)BE
[강점]
(주강사) 소스코드 상 기능적 결함 없이 스프링 boot 3-tier 패키지 모듈화 및 OOP 서비스 계층 분리가 잘 이루어졌으며, HandlerInterceptor 세션 인증 처리 및 JdbcTemplate 1:N 조인 매핑 등의 문제 상황을 6가지 트러블슈팅 문서로 정리했습니다.
(보조강사) Controller, Service, Repository의 역할을 구분하여 전체적인 프로젝트 구조를 구성했습니다.

[보완사항]
(주강사) 컨트롤러 예외 처리를 전역 처리 클래스(GlobalExceptionHandler)로 공통화하고 파라미터 유효성 검증 예외 처리를 보완하는 작업을 추천합니다.
(보조강사) 데이터 검증은 프론트뿐만 아니라 서버에서도 체크하면 더욱 안정적일 것 같습니다.

■ 6. 완성도 및 태도 (10점) — 협업/발표
[강점]
(주강사) 깃허브 이슈의 구체적인 작업 등록과 풀 리퀘스트 기반의 충실한 작성 및 피드백, 기능별 브랜치 사용과 PR 코드 리뷰 프로세스를 통해 기능 단위 병합 협업을 체계적으로 진행했습니다.
(보조강사) 이슈를 단순 기록 용도로 사용하지 않고 실제 개발 작업과 연결하여 관리했으며, 팀원 간 코드 확인 및 피드백 과정도 확인 가능합니다.

[보완사항]
(주강사) 프로젝트 완료 후 유지보수성을 위해 코드 컨벤션 및 정적 분석 규칙을 추가 정립하면 좋습니다.
(보조강사) 코드 작성 규칙(코딩 컨벤션)을 정하여 프로젝트를 작성하면 추후 유지보수 시 안정적으로 진행할 수 있을 것 같습니다.

■ 종합 의견
-주강사: 1팀은 프로젝트 초반부터 체계적인 문서 정리가 수행되었으며, 소스코드 구조와 산출물 작성, 깃허브 협업 이력 측면에서 전반적으로 완성도 높은 결과를 보여주었습니다. 다양한 기능 구현에도 불구하고 문서화 및 개발 작업이 프로젝트 본래 일정에 맞춰 안정적으로 마무리되었습니다. 작성된 5대 설계 문서와 TUI Editor 폼 충돌, Interceptor 리다이렉트 무한 루프, RowMapper 매핑 등을 다룬 6가지 트러블슈팅 보고서는 개발 과정에서 겪은 기술적 문제를 차근차근 해결한 과정을 잘 보여줍니다. 또한 깃허브 이슈 관리와 마일스톤 스크럼 운영, 브랜치 작업 및 PR 병합을 지속적으로 실천하며 팀 프로젝트를 진행했습니다.

-보조강사: 프로젝트 기획부터 개발, 협업 과정까지 전반적으로 균형 있게 잘 이끌어간 프로젝트입니다. 초반에 요구사항을 기능별로 잘 쪼개고 우선순위를 정해둔 덕분에 개발 방향이 흔들리지 않았고, 단순 기록용이 아닌 실제 작업과 연결된 깃허브 이슈 관리나 팀원 간 코드 피드백 과정이 매우 매끄러웠습니다. 기술적으로도 프론트에서는 타임리프 프래그먼트로 중복을 줄이고 외부 라이브러리를 적재적소에 활용한 점, 백엔드에서는 계층 구조와 외래키 설계를 깔끔하게 잡아둔 점이 좋았습니다.
